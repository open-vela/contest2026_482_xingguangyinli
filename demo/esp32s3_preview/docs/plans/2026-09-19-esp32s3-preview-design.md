# Living Canvas ESP32-S3 独立演示版设计

## 目标

在全新的 Waveshare ESP32-S3-Touch-AMOLED-1.8 V2 上运行一套独立的 Living Canvas 比赛演示。屏幕使用 368×448 原生竖屏；开机进入主页并循环播放 `circle.mp4` 转换得到的轻量动画；触摸后进入晚餐主题的离线演示流程。

## 工程边界

- 本工程位于 `local-setup/living_canvas_esp32s3_preview`，拥有独立 Git 历史、构建产物和烧录脚本。
- Gemini-S1/openvela 工程 `local-setup/contest2026_482_xingguangyinli` 不做任何修改。
- 不复用任何其他产品的逻辑、角色、网络接口或命名。只参考已经在同型号新板上验证过的 CO5300 显示、CST820 触摸和 IO 扩展器初始化方式。
- 第一版是离线独立演示，不依赖 Wi-Fi、AI 后端、语音或云服务。

## 交互流程

1. 上电后短暂显示 Living Canvas 启动画面。
2. 进入主页，循环播放由 `circle.mp4` 转换出的竖版帧序列。
3. 点击主页后显示 `sitting.png` 菜单底图，桌面左、中、右分别是外卖、盲盒、在家做饭三个入口。
4. 第一次点击入口显示高亮，第二次点击同一入口确认；左上角返回按钮允许随时纠错。
5. 外卖流程演示语音需求、多 Agent 分析、推荐结果和可扫描二维码；盲盒流程显示四个文字盒子；做饭流程演示“番茄＋鸡蛋”的预设菜谱。
6. 结果页停留 8 秒后自动回到主页循环动画。

## 显示与素材策略

- 屏幕固定为 368×448 原生竖屏，不做 90 度横屏旋转。
- 原始 PNG/MP4 永不覆盖；构建工具只在工程的 `generated/` 目录生成板端资源。
- `circle.mp4` 通过 macOS AVFoundation 等距抽取 18 帧，裁切为屏幕比例，再量化为 RGB565，按 450 ms/帧循环。
- 菜单只使用正确的 `sitting.png`；用户指出有误的三张独立元素图不进入板端资源。
- 明天替换的新 UI 或视频沿用同一 368×448 资源接口和触摸热区，不改状态机主流程。

## 软件结构

- `src/living_canvas_state.*`：纯 C++ 状态机，不依赖 Arduino，负责页面顺序、点击跳转和主页循环计时。
- `src/living_canvas_assets.*`：生成资源的统一索引与元数据。
- `living_canvas_esp32s3_preview.ino`：板级初始化、Arduino_GFX 显示、触摸适配、定时器和渲染入口。
- `tools/`：只在 Mac 上运行的素材检查、抽帧和资源转换工具。
- `tests/`：在 Mac 上验证状态机、资源尺寸、帧数、容量上限和品牌边界。

## 存储与运行约束

- 使用 16MB Flash 的 `app3M_spiffs9M_fact512k_16MB` 分区方案。
- 固件代码和小型元数据进入应用分区；大图和动画资源进入独立 SPIFFS 数据镜像，避免应用分区溢出。
- 使用 8MB PSRAM 存放一个 329,728 字节全屏帧缓冲。
- 动画以 18 帧、450 ms/帧稳定循环；现场展示稳定性优先。

## 安全与验收

- 烧录前通过 esptool 再次读取芯片 MAC，只允许本地 `EXPECTED_ESP32_MAC` 指定的目标。
- 明确排除私密配置中登记的非目标串口；真实串口号不进入仓库。
- 构建前运行主机测试；构建后记录固件和文件系统镜像 SHA-256。
- 烧录后读取启动日志，确认 368×448 显示、触摸初始化、资源挂载和主页动画启动。
- Gemini-S1 工程在整个过程中保持 Git 状态不变。
